**Goal:** Build fix-ui v1 — core package, npm embed, Chrome MV3 extension, and the fixui-bridge daemon (HTTP + SSE + MCP), with unit, contract, and Playwright e2e tests.

**Architecture:** One zero-dependency core (picker, selector builder, schema, transport, console buffer, review-channel client) consumed by two adapters (embed, extension); a single local bridge daemon owns per-project JSONL inboxes and brokers agent-initiated reviews over SSE; agents integrate via MCP or the file. See README.md's diagram.

**Tech Stack:** TypeScript 5.9 strict, ESM only, pnpm 11 workspace, vitest 3 (+jsdom) for unit/contract tests, @playwright/test for e2e, esbuild for the extension bundle, @modelcontextprotocol/sdk for MCP.

## Global Constraints

Copied from the spec — every task implicitly includes these:

- Package names: `@hulbu/fixui-core` (packages/core), `@hulbu/fixui` (packages/embed), `fixui-bridge` (packages/bridge, bin `fixui-bridge`), Chrome extension in `extension/`. Monorepo shape per docs/design.md "Monorepo shape".
- Zero runtime dependencies in core, embed, extension (embed: `react >=18` **optional** peer only). Bridge: node stdlib + `@modelcontextprotocol/sdk` only.
- Bridge binds loopback only, default `http://127.0.0.1:3499`; `--port N` / env `FIXUI_PORT` override (tests need this).
- Inbox `.fix-ui.jsonl`, review records `.fix-ui.reviews.jsonl`, at the target project root. Resolved entries are removed (rewrite minus id), no tombstones.
- Wire format exactly per docs/capture-format.md: FeedbackEntry v1 (`v:1`); `project` is wire-only (bridge routes on it, falls back to bridge cwd, strips before writing); unknown fields preserved; `elementText` ≤120 chars; `consoleErrors` deduped ring buffer max 5, message ≤300, source ≤160, warnings never collected.
- HTTP surface: `POST /entries`, `GET /entries` → `{entries}`, `DELETE /entries/:id` AND prototype body-style `DELETE /entries` `{id}`, `GET /events` (SSE), `POST /reviews` (agent-side, long-poll — responds only when resolved), `POST /reviews/:id/verdict`, `GET /healthz` → `{ok:true,name:"fixui-bridge",version}`. CORS: `Access-Control-Allow-Origin: *` + OPTIONS preflight on all routes (browser adapters POST cross-origin).
- SSE events: `review-requested` `{reviewId,prompt,url?,timeoutSeconds}`, `review-cancelled` `{reviewId}`; comment-line heartbeat every 15s; on connect, replay the currently-pending review for that project if any (page reloads must re-arm).
- Review verdicts: `"approved" | "changes" | "timeout" | "no-reviewer"`. `busy` is an error, not a verdict; one pending review per project. No adapter connected → immediate `no-reviewer`.
- MCP tools: `list_feedback`, `resolve_feedback`, `request_review` per docs/agent-integration.md "Tool shape" (progress notifications while waiting).
- Picking mechanics 1–5 in docs/design.md are hard requirements (top-layer popovers, modal re-homing via MutationObserver on `dialog[open]`, window-capture listeners, full pointer-sequence suppression, selector quality: stable ids/attrs then `:nth-of-type`, always pair selector + component + elementText).
- Accent default `#ef5b2a`; floating chip default on.
- TDD per task; every task ends with `pnpm -r typecheck && pnpm -r test` green at the repo root and a commit. Never commit `node_modules`, `dist`, `.fix-ui*.jsonl`.
- Core boundary: core never touches network/DOM-mount decisions except through injected `transport` / `mount` / injected IO impls; core knows nothing of chrome.* or the bridge filesystem.

```ts
// entry.ts
export interface ConsoleError { message: string; source?: string; count: number; lastAt: string }
export interface FeedbackEntry {
  v: 1; id: string; note: string; selector: string;
  component?: string; elementText?: string; url: string;
  viewport: { width: number; height: number }; userAgent: string;
  createdAt: string; consoleErrors?: ConsoleError[]; project?: string;
}
export function validateEntry(x: unknown): x is FeedbackEntry; // shape + length caps per capture-format.md
export function buildEntry(input: { note: string; selector: string; component?: string; elementText?: string; project?: string; consoleErrors?: ConsoleError[] }, env: { url: string; viewport: {width:number;height:number}; userAgent: string; now?: () => Date; uuid?: () => string }): FeedbackEntry;

// console-buffer.ts
export interface ConsoleBuffer {
  install(target?: Window): void;  // wraps window.onerror addEventListener('error'/'unhandledrejection') + console.error; idempotent
  uninstall(): void;
  push(message: string, source?: string): void;  // manual feed (extension MAIN-world postMessage path)
  snapshot(): ConsoleError[];      // deduped by message, most recent last, caps applied
  clear(): void;
}
export function createConsoleBuffer(opts?: { maxErrors?: number; maxMessage?: number; maxSource?: number }): ConsoleBuffer; // defaults 5/300/160

// transport.ts
export interface TransportOptions {
  endpoint: string;                 // absolute or path, e.g. "http://127.0.0.1:3499/entries" or "/api/ui-feedback"
  project?: string;                 // stamped onto outgoing entries when set
  fetchImpl?: typeof fetch; storage?: Pick<Storage,"getItem"|"setItem"|"removeItem">;
  clipboard?: (text: string) => Promise<void>;
  onQueueChange?: (pending: number) => void;
}
export interface Transport {
  create(entry: FeedbackEntry): Promise<{ ok: boolean; queued: boolean }>;
  list(): Promise<FeedbackEntry[]>;
  remove(id: string): Promise<boolean>;   // body-style DELETE {id} — works against bridge AND prototype-style app routes
  flush(): Promise<void>; destroy(): void;
}
export function createTransport(opts: TransportOptions): Transport;
```

Behavior (docs/design.md "Error handling"): failed `create` → queue in memory + storage key `"fixui.queue.v1"`, retry with exponential backoff 1s→2s→4s→…→30s cap; after 5 consecutive failed flushes of an entry, invoke `clipboard` with the entry JSON and drop it from the queue (report via `onQueueChange`). `list` returns `[]` on network failure. Deduplicate storage-restored queue by id.

export interface PickerOptions {
  transport: Transport;
  mount?: Element | ShadowRoot;      // default document.body; extension passes its shadow root
  capture?: { consoleErrors?: () => ConsoleError[]; componentName?: (el: Element) => string | undefined };

export interface ReviewRequest { reviewId: string; prompt: string; url?: string; timeoutSeconds?: number }
export interface ReviewVerdict { reviewId: string; verdict: "approved" | "changes"; entryIds: string[] }

  startReview(req: ReviewRequest): void;   // show banner (prompt + Approve / Request changes), arm picker, track entry ids

**Interfaces:**
- Consumes: Task 4's server/state, storage.
- Produces: the complete bridge. MCP tools (exact): `list_feedback({project?}) → {entries}`; `resolve_feedback({id, project?}) → {ok}`; `request_review({prompt, url?, timeoutSeconds?, project?}) → {verdict, entries, durationMs}` with defaults `timeoutSeconds=600`.

Behavior (docs/agent-integration.md Direction 2 — binding):
- `POST /reviews` `{prompt,url?,timeoutSeconds?,project?}` is the agent-side entry (used by proxy mode and tests): held open, responds `{verdict, entries, durationMs}` only on resolution. MCP `request_review` calls the same broker in-process (daemon) or via this route (proxy), emitting MCP progress notifications every 10s ("waiting for reviewer, Ns…").
- No SSE subscriber for the project → immediate `no-reviewer`. Second review for a busy project → HTTP 409 / MCP tool error `busy`. Timeout → verdict `timeout` + `review-cancelled` SSE event.
- `GET /events?project=` SSE: emit `review-requested` on request AND on connect if one is pending; 15s heartbeat comments; `review-cancelled` on timeout/abort.
- `POST /reviews/:id/verdict` `{verdict:"approved"|"changes", entryIds}` → resolves the held call with the full entries looked up from the inbox by `entryIds`, appends `{id,prompt,verdict,entryIds,requestedAt,resolvedAt}` to `.fix-ui.reviews.jsonl`. Unknown id → 404.
